# 单模块提示词文本示例

> 本示例在**不接授权、不联网**的情况下即可复现：
>
> ```bash
> cd fix-prompt
> python3 build_prompt.py --list --data examples/demo_table.csv
> python3 build_prompt.py --submodule "订单管理-订单查询" --data examples/demo_table.csv
> python3 build_prompt.py --submodule "库存管理-库存盘点" --data examples/demo_table.csv
> ```
>
> （接好授权后，把 `--data examples/demo_table.csv` 去掉即为实时取数。）

---

## 一、`--list` 输出

```
可选功能子模块（共 2 个）—— 名称 | 功能点数量：
   3 | 库存管理-库存盘点
   2 | 订单管理-订单查询

用法：在斜杠命令后接功能子模块名，例如
  /fix-prompt 订单管理-订单查询
（脚本对应：python3 build_prompt.py --submodule "<名称>"）
```

> 示例表里还有「报表中心-销售报表」和「订单管理-订单查询 / 导出查询结果」，
> 它们因为**已整改（`TRUE`）**或**负责人不是张三**或**测试已通过**被筛掉了 —— 这正是筛选口径生效的体现。

## 二、风格 A：各功能点有独立功能描述

`python3 build_prompt.py --submodule "库存管理-库存盘点" --data examples/demo_table.csv`

```markdown
# 功能子模块整改提示词

## 功能子模块
库存管理-库存盘点

## 功能点清单（共 3 个）

### 功能点 1：生成盘点单
- 功能说明：按仓库与日期生成盘点单，明细行取当前账面库存
- 菜单页路径：库存中心 / 库存管理 / 库存盘点
- 测试反馈：生成后明细行为空

### 功能点 2：盘点差异调整
- 功能说明：差异数量调整后同步更新库存台账并留痕
- 菜单页路径：库存中心 / 库存管理 / 库存盘点
- 测试反馈：调整后库存台账未更新

### 功能点 3：盘点单审核
- 功能说明：审核盘点单并锁定明细，锁定后不可再编辑
- 菜单页路径：库存中心 / 库存管理 / 库存盘点
- 测试反馈：审核通过后明细仍可编辑

## 你的工作
你是一名全栈开发 agent。请基于本项目（前端 + 后端 + 数据库等全栈代码），对上述「库存管理-库存盘点」下的全部功能点测试反馈进行全栈改造。要求：
1. **先给出改造方案**：明确影响范围、涉及的前后端文件/接口、数据结构变更、实现步骤与风险；方案经确认后再动手编码。
2. **逐条对照测试反馈**：定位每条不通过的根因并修复，确保与功能说明一致。
3. **自测与验证**：修复后给出自测步骤与预期结果，说明如何在对应菜单页路径下验证。
4. 保持改动最小且聚焦本子模块，不引入无关变更。
```

## 三、风格 B：整组共享一段功能描述（源表合并单元格）

`python3 build_prompt.py --submodule "订单管理-订单查询" --data examples/demo_table.csv`

描述提升为「功能子模块简介」章节，功能点条目不再逐条重复。

```markdown
# 功能子模块整改提示词

## 功能子模块
订单管理-订单查询

## 功能子模块简介
支持按订单号精确查询订单，并展示订单基本信息

## 功能点清单（共 2 个）

### 功能点 1：按订单号查询
- 菜单页路径：订单中心 / 订单管理 / 订单查询
- 测试反馈：输入订单号后列表为空，接口返回 500

### 功能点 2：按状态筛选
- 菜单页路径：订单中心 / 订单管理 / 订单查询
- 测试反馈：状态下拉选项与数据字典不一致

## 你的工作
你是一名全栈开发 agent。请基于本项目（前端 + 后端 + 数据库等全栈代码），对上述「订单管理-订单查询」下的全部功能点测试反馈进行全栈改造。要求：
1. **先给出改造方案**：明确影响范围、涉及的前后端文件/接口、数据结构变更、实现步骤与风险；方案经确认后再动手编码。
2. **逐条对照测试反馈**：定位每条不通过的根因并修复，确保与功能说明一致。
3. **自测与验证**：修复后给出自测步骤与预期结果，说明如何在对应菜单页路径下验证。
4. 保持改动最小且聚焦本子模块，不引入无关变更。
```

## 四、用户后续动作（闭环）

1. 复制上面整段文本 → 粘贴给 coding agent 编码；
2. coding agent 先给改造方案、编码、逐条修复、自测；
3. 你验收 + 截图，回在线表格把该子模块的「整改情况」改为 `TRUE`（打钩）；
4. 下一个子模块：重新触发 `/fix-prompt <下一个子模块名>`。

> 每次触发只产出**一段**自包含提示词；本 skill 不自动批量生成、不写执行目录。
